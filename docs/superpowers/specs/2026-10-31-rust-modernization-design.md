## 方案比较与推荐

1. **推荐：原生 Win32 Rust 现代化。** 保留小工具的原生体验，使用微软官方绑定，重构状态与资源管理，完成配置和发布链路。现有行为与集成测试可以继续作为迁移参照。
2. egui 或 Slint 重建主界面。控件布局更容易统一，但仍需 Win32 负责置顶、选窗、托盘和徽标，增加渲染依赖与两套事件循环的集成成本。
3. 仅更新 Cargo 元数据和替换图片。改动小，但继续依赖旧目录、手写 ABI 和解析器，不满足全面现代化目标。

采用方案 1。不引入 WebView 或浏览器运行时。

## Rust 架构与依赖

### 系统接口

使用微软 windows-sys 的当前稳定版，启用实际需要的 Win32 功能。查询时 crates.io 最新版为 0.61.2；实施时核实兼容性并锁定 Cargo.lock。

删除手写 Win32 函数声明与重复结构定义，使用官方句柄、常量、结构和回调类型。平台封装集中处理 null 句柄、GetLastError、坐标和 UTF-16。扩展 RECT 的辅助方法使用 Rust 扩展 trait 或本地几何类型，不为官方类型添加固有实现。

对拥有所有权的图标、光标、位图、DC、菜单、钩子及互斥体建立明确释放路径；借用的窗口句柄和系统共享资源不得误释放。外部回调不允许发生 RefCell 重入借用崩溃或 unwind 穿过系统 ABI。窗口事件通知投递到 UI 线程处理，外部 API 调用避免放在持有状态可变借用的代码段内。

模块按职责拆分：纯业务与键盘组合、配置、平台资源及窗口接口、置顶状态、选窗遮罩、主界面、托盘、设置。避免仅为拆文件而新增抽象。

### 配置与 CLI

用 serde + serde_json 替代手写 JSON 解析。保留 PascalCase 字段、快捷键字符串和 null 禁用语义、缺省值和未知字段兼容性。正确处理 Unicode 转义、路径反斜杠和无效 JSON。

优先读取 %APPDATA%\\PinWin\\settings.json，不存在时读取工作目录 settings.json；旧相对图标路径继续兼容。保存采用同目录临时文件与原子替换方案，失败时保留旧文件并反馈错误。保留原有透明度范围 30..=255，界面显示与 CLI 帮助一致。

用 clap 当前稳定版本整理 CLI 参数和帮助，保留已有命令、窗口句柄十进制/十六进制输入及退出码约定。仅在最终实现中确有用途时保留依赖，不为追求“更新”添加闲置库。

### 窗口生命周期与错误处理

- PinManager 仅管理本应用拥有的置顶记录；退出及取消全部不能改动其他应用的无关窗口。
- 记录目标原始置顶、layered、透明度和穿透状态；取消置顶恢复可恢复的原始属性，避免破坏原本透明的目标。仅在实际读取成功时声称能够恢复某项状态。
- 目标销毁后清理徽标和状态，避免延迟事件误操作复用的 HWND。
- 对 SetWindowPos、快捷键冲突、资源加载、配置保存等失败给出可理解的信息。
- 窗口标题读取设定超时；外部应用失去响应不能无限阻塞 UI。
- 继续使用事件通知与低频健康检查，不恢复旧版 10ms 轮询。

## AI 图标方案

保留原图“红色斜向图钉”的识别元素，重绘成适合 Windows 10/11 的简洁、清晰图形。透明背景、无文字、避免细碎装饰，兼顾浅色和深色桌面。图标重绘不扩展为整个主界面视觉改版。

交付资源覆盖四个角色：

1. 应用/EXE 图标：完整图钉标识，多尺寸 ICO。
2. 托盘图标：使用同一视觉体系，16/20/24/32 像素清晰可读。
3. 置顶徽标：紧凑透明图钉，可点击且按 DPI 缩放。
4. 选窗光标：带明确热点的瞄准符号，生成正确 CUR 或通过系统 API 构建光标；不得将 HICON 直接当作具有正确热点的光标使用。

调用可用 AI 图像生成工具制作原始图像，并将源 PNG、提示词、转换说明保存在 assets/ 下。用 Rust 资源工具配合 image 库转换缩放与编码，生产构建不依赖 Python 或在线生成。缩小图形在透明背景、浅/深底色下人工检查，必要时对小尺寸做确定性清理。

资源改为 assets/ 下独立文件。图标和徽标使用支持 alpha 的系统渲染，替代旧 BMP 色键透明假设。运行时全部内嵌，无需安装 Images 文件夹。用户自定义资源路径仍可用。
